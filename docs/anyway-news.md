# Anyway News в NabyScape

Необязательный новостной модуль в форке [NabyScape](https://github.com/BillyNabil/nabyscape).
Это сборка приложения с новым виджетом: у NabyScape пока нет загрузчика внешних плагинов.
Лицензия исходного приложения и модуля — MIT.

## Подключение

1. Распакуйте portable-архив и запустите `NabyScape.exe`.
2. Settings → Widgets & tools → Your widgets → включите **Anyway News**.
3. Откройте виджет через точки навигации в шторке. Название видно при наведении.
4. В «Подключении» оставьте `https://news.anyway-community.ru/api` и нажмите «Подключить».

«Сводка» показывает общую редакционную подборку нашего бота. «Лента» — последние
публичные новости. Нажмите на заголовок, чтобы раскрыть текст и ссылку.
Сноски источников видны и в закрытой карточке. Источники, упоминающие событие,
не считаются подтверждением его достоверности.

**Состояние серверного API:** публичная сводка уже работает. Новый endpoint ленты
подготовлен в [ветке Anyway News](https://github.com/cyxar4uk/anyway-news/tree/codex/nabyscape-api)
и проверен локально с базой в режиме только чтения. В рабочий API он пока не выложен.
До выкатки вкладка «Лента» честно сообщает об отсутствии endpoint; сводка работает.
Для локального API укажите `http://127.0.0.1:8766/api`.

Встроенная проверка обновлений NabyScape по-прежнему смотрит upstream-релизы.
Установка upstream-сборки заменит эту версию и уберёт новостной модуль;
сборки этого форка берите из его раздела Releases.

## API

Адрес подключения — корень API, включая `/api`, если он есть.
Поддерживаются HTTPS и HTTP на loopback. URL с логином, паролем, query или fragment
не принимаются. Redirects не выполняются. Токен бота, initData, developer/admin
секреты, cookies и профиль читателя этому модулю не нужны.

`GET {base}/v2/digest` — существующий формат Anyway News:

```json
{"title":"Главное за вечер","time":"20:00","items":[
  {"postId":"123","head":"Заголовок","nsrc":3,"notes":[]}
]}
```

`GET {base}/v2/integrations/news/feed` — открытый интерфейс для виджетов:

```json
{"version":1,"title":"Лента новостей","personalized":false,
 "updatedAt":"2026-11-24T20:00:00+00:00","items":[
  {"id":"123","title":"Заголовок","summary":"Краткий текст",
   "source":"Название редакции","publishedAt":"2026-11-24 23:00",
   "url":"https://example.org/news/123","notes":[]}
]}
```

`publishedAt` в текущем адаптере — время МСК, как в базе Anyway News.
Реализация другого сервиса может отдавать такой же JSON. HTML не исполняется;
ссылки открываются только по нажатию и только с HTTP(S)-схемой.

## Обновление и данные

Виджет выключен по умолчанию и не обращается к сети до подключения.
Во время просмотра данные обновляются раз в пять минут; скрытый виджет не опрашивает API.
Кнопка обновления ограничена интервалом 15 секунд. Таймаут — 15 секунд,
потолок ответа — 1 МиБ, до 5 пунктов сводки и 20 новостей.
Кэш находится только в памяти процесса и разделён по адресу API и вкладке.
При сбое сохраняется прежний список и показывается ошибка. Время «Обновлено»
означает время получения ответа клиентом, а не время публикации новости.
«Отключить» прекращает запросы; состояние хранится в штатных настройках NabyScape.

## Проверка и сборка

Требуется .NET 10 SDK на Windows. Полная сборка и штатные проверки:

```powershell
./build.ps1 -OutputDirectory artifacts-anyway
```

Изолированная проверка WPF на тестовых данных, без новостного сервера:

```powershell
./artifacts-anyway/NabyScape.exe --diagnostics ./outputs/news --isolated-diagnostics --news-only
```

Она проверяет сводку, ленту, границы окна, ширину 300/526 DIP и светлую тему;
PNG и отчёт сохраняются в `outputs/news`. Тестовые новости явно подписаны.
Для ручного запуска той же диагностики с работающим локальным API:

```powershell
$env:NABYSCAPE_NEWS_API = 'http://127.0.0.1:8766/api'
./artifacts-anyway/NabyScape.exe --diagnostics ./outputs/news-live --isolated-diagnostics --news-only --news-live
```

Автоматическая проверка среды запретила оконный прогон с локальным HTTP API.
Поэтому в этой поставке WPF проверен на изолированных данных, а реальный HTTP API
и база — отдельно. Это ограничение проверки, а не подтверждённый сбой приложения.
